Home servers tend to grow by hand: a file edited over SSH, a cron job nobody remembers, an image last updated two years ago. I wanted the smallest example of the opposite, a server run entirely by its own git repository.

[git-a-home-server](https://github.com/splch/git-a-home-server) is eight files and about 230 lines.

```
git push → Forgejo → runner → docker compose up -d --wait
```

- **One file.** `compose.yaml` holds every service: Caddy as the front door, Forgejo for git and CI, and whatever you add.
- **Deploys.** Pushing to `master` applies the file and waits for every health check, so the health checks are the tests.
- **Updates.** Renovate opens a pull request for each new image version. CI boots a throwaway copy of the stack, and minor and patch updates merge themselves if it comes up healthy.
- **Backups.** A nightly job pauses the services, snapshots every Docker volume with restic, and resumes them, usually within seconds.

Starting it takes two commands:

```sh
git clone https://github.com/splch/git-a-home-server && cd git-a-home-server
./bootstrap.sh
```

## What was harder than it looked

**CI that deploys its own CI.** A job cannot replace the runner it is running on. The deploy ends by starting a detached container that asks the runner to stop; the runner finishes the job first and is then replaced. This only works with `shutdown_timeout` set, because by default the runner cancels its job the moment it is told to stop.

**Compose ignores config changes.** Change only an inline `configs:` block and `docker compose up` does nothing, so a new Caddy route never goes live. The maintainers [do not plan to change this](https://github.com/docker/compose/issues/11900). The fix is to repeat the config as a label on the service, using a YAML alias.

**Backups that restore.** Forgejo's SQLite database can be copied mid-write into a file that will not open. Pausing the containers first makes the copy what a power cut would leave, which databases are built to survive. Deleting every volume and restoring brought back Forgejo, its repositories, and the runner.

It leaves out whatever depends on your network: off-site backups, HTTPS, and remote access are listed in the README.
